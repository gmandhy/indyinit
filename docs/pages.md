### Required Page Designs (User Flow)

To support these routines and the clinical tracking requirements, the application requires the following distinct page designs (or distinct UI states within a Single Page Application):

**1. Patient Workstation (The Exercise Interface)**
This is the primary interactive screen where the patient performs their exercises. It needs to be designed as a split-screen or overlay interface.

* **Live Webcam Canvas Viewport:** The main focus, displaying the patient's hand with the MediaPipe skeletal overlay.
* **Holo Target Overlay:** The interactive 3D spatial buttons that the patient must reach or dwell within.
* **Live Goniometer HUD:** A clean, unobtrusive overlay displaying real-time joint angles (e.g., "Index PIP: 45°").
* **Compensatory Cheat Warning Banner:** A prominent visual alert (e.g., flashing red border or toast notification) that triggers when the wrist deviation threshold is exceeded.
* **Desk Tap Waveform Visualizer (Conditional):** An audio waveform or impulse bar that appears only during Desk Tap routines, providing visual confirmation of acoustic impacts.
* **"Ghost Hand" Overlay (P2):** A toggleable translucent wireframe of the patient's baseline performance rendered beneath their live hand.

**2. Therapist/Clinical Setup & Calibration**
This screen allows the clinician (or the system autonomously) to define the parameters of the exercise session.

* **Hand Size Calibration Modal:** A quick 5-second flow where the patient holds an open palm to the camera to calculate the `PalmUnit` (distance from wrist to middle knuckle).
* **Healthy Hand Mirroring Flow (P2):** A guided process to scan the healthy hand, perform a baseline stretch, and generate mirrored spatial targets for the injured hand.
* **Routine Prescription Builder:** An interface for therapists to select the exercise type (ROM arc, Tapping), set target angles, define dwell times, and adjust the strictness of the wrist-cheat guardrail.

**3. Telemetry & Progress Dashboard**
This is the post-session review screen for both the patient and the therapist.

* **Baseline vs. Current Performance Charts:** Line or bar charts comparing today's ROM degrees and tap frequencies against historical baselines.
* **Fatigue Decay Graph:** A specialized chart plotting tap speed (Hz) over the 15-second test interval to visualize motor fatigue.
* **Quality Metrics Summary:** Readouts detailing the total number of repetitions, the number of wrist compensations flagged, and the overall success rate.

**4. Clinical Documentation (SOAP Note) Generator**
A dedicated view for the therapist to review and approve the AI-generated medical documentation.

* **Structured SOAP Note Panel:** Displays the Subjective, Objective, Assessment, and Plan text generated by the LLM based on the session's JSON telemetry.
* **CPT Code Justification List:** A clear breakdown of suggested billing codes (e.g., 97110, 98977) with the specific telemetry data points justifying their use.
* **Adaptive Prescription Preview:** Shows the system's recommended adjustments for the next session (e.g., "Increase spatial target radius by 10%").

**5. Factory Observability HUD (Hackathon Specific)**
A developer-focused panel required to score points in the "Software Factory" track.

* **Live Performance Metrics:** A compact drawer or footer displaying inference FPS, frame latency (ms), and the status of the local API endpoints.
* **Security & Privacy Badge:** Visual confirmation that the system is operating in a "Zero-Video-Egress" mode (processing all camera data locally).
* **Unit Test Status (Optional UI):** A readout confirming that the deterministic biomechanical math tests are passing.
